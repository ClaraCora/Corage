# Windows 服务内核启动失败修复说明

最后验证：2026-08-26

适用版本：Clash Verge Rev 2.5.2、2.5.4-rc.1 及使用同一 Windows 服务认证机制的版本

## 1. 现象

安装服务后，应用无法通过 Service 模式启动内核，日志中出现：

```text
failed to start Service core at C:\Program Files\Clash Verge\verge-mihomo.exe: owner credential path has an unexpected owner
```

有些机器可能看到相近的错误：

```text
owner token file has an unexpected owner
service protocol version does not match
Some issue with service IPC Path: 系统找不到指定的文件。 (os error 2)
```

回退到 2.5.2 后仍然出现同样的错误，通常说明问题在本机权限或服务残留状态，而不是内核文件本身。

## 2. 根因

Windows 服务启动内核前会校验两层身份：

1. 用户数据根目录的属主必须是当前登录用户；
2. `.clash-verge-service-owner-token` 必须是当前用户拥有的 32 字节凭据文件，并具有受保护的访问控制列表。

本次确认到的典型异常是：

```text
用户数据目录属主：BUILTIN\Administrators
当前登录用户：    CC\ccios
token 文件属主：   CC\ccios
```

也就是说，token 文件本身没有问题，但它所在的目录是管理员组属主。服务校验的是整个凭据路径，因此仍会拒绝请求。

常见产生原因：

- 以管理员身份启动应用后创建了 `%APPDATA%` 下的应用目录；
- 升级、回退版本或手动安装服务时留下了管理员组属主；
- 服务程序和应用程序来自不同版本，协议版本不一致；
- 服务安装失败后留下了未注册服务的运行时文件或旧锁。

这不是普通的 `.repair.lock` 首先导致的错误。看到 `owner credential path` 时，应先检查属主。

## 3. 先诊断，不要删除配置

以下命令可以在普通 PowerShell 中执行。涉及修改属主或安装服务时，需要管理员 PowerShell/UAC 确认。

```powershell
$appDataRoot = Join-Path $env:APPDATA 'io.github.clash-verge-rev.clash-verge-rev'
$tokenPath = Join-Path $appDataRoot '.clash-verge-service-owner-token'

Write-Output "当前用户：$([System.Security.Principal.WindowsIdentity]::GetCurrent().Name)"
Write-Output "当前 SID：$([System.Security.Principal.WindowsIdentity]::GetCurrent().User.Value)"
Write-Output '=== 应用数据目录 ==='
Get-Item -LiteralPath $appDataRoot -Force | Format-List FullName,Mode,Attributes
Get-Acl -LiteralPath $appDataRoot | Format-List Owner,AccessToString
Write-Output '=== owner token ==='
Get-Item -LiteralPath $tokenPath -Force | Format-List FullName,Length,Attributes
Get-Acl -LiteralPath $tokenPath | Format-List Owner,AccessToString
Write-Output '=== Windows service ==='
sc.exe query clash_verge_service
```

判断方式：

- `owner credential path has an unexpected owner`：检查并修复 `$appDataRoot` 的属主；
- `owner token file has an unexpected owner`：检查并修复 `$tokenPath` 的属主和 DACL；
- `service protocol version does not match`：当前应用和已安装服务版本不一致，应使用当前安装包的服务安装器重装；
- `sc.exe query` 返回 1060 且没有服务注册：服务没有真正注册成功，再检查安装器和服务目录残留；
- 只有在服务未注册、且 `C:\ProgramData\clash-verge-service` 中明确存在陈旧锁时，才处理旧锁。

## 4. 推荐修复步骤

### 4.1 修复用户数据目录属主

先退出 Clash Verge，打开管理员 PowerShell，执行：

```powershell
$appDataRoot = Join-Path $env:APPDATA 'io.github.clash-verge-rev.clash-verge-rev'
$owner = (whoami).Trim()

icacls.exe $appDataRoot /setowner $owner
Get-Acl -LiteralPath $appDataRoot | Select-Object Owner
```

最后一条命令应显示当前登录用户，例如：

```text
Owner
-----
CC\ccios
```

此步骤只修改应用数据根目录的属主，不递归修改配置文件，不删除配置、订阅、节点或 token。

### 4.2 修复 token 文件属主

如果错误明确是 `owner token file has an unexpected owner`，并且 token 文件仍是 32 字节普通文件，可以先只修复它的属主：

```powershell
$appDataRoot = Join-Path $env:APPDATA 'io.github.clash-verge-rev.clash-verge-rev'
$tokenPath = Join-Path $appDataRoot '.clash-verge-service-owner-token'
$owner = (whoami).Trim()

icacls.exe $tokenPath /setowner $owner
Get-Item -LiteralPath $tokenPath -Force | Select-Object FullName,Length,Attributes
Get-Acl -LiteralPath $tokenPath | Format-List Owner,AccessToString
```

如果文件不是 32 字节、是目录/链接、或修复属主后仍提示 token 安全属性异常，退出应用后仅备份并删除这个 token 文件，让应用重新生成：

```powershell
$appDataRoot = Join-Path $env:APPDATA 'io.github.clash-verge-rev.clash-verge-rev'
$tokenPath = Join-Path $appDataRoot '.clash-verge-service-owner-token'
$backupPath = "$tokenPath.bak-$(Get-Date -Format 'yyyyMMdd-HHmmss')"

Copy-Item -LiteralPath $tokenPath -Destination $backupPath -Force
Remove-Item -LiteralPath $tokenPath -Force
```

不要删除整个 `%APPDATA%\io.github.clash-verge-rev.clash-verge-rev` 目录。

### 4.3 用当前版本安装器重装服务

应用和服务必须来自同一个安装包。以当前版本安装器为准，不要混用 2.5.2 和 2.5.4 的服务文件。

```powershell
$installer = 'C:\Program Files\Clash Verge\resources\clash-verge-service-install.exe'
Start-Process -FilePath $installer -Verb RunAs -Wait
sc.exe query clash_verge_service
```

成功时应看到：

```text
SERVICE_NAME: clash_verge_service
STATE              : 4  RUNNING
```

如果当前安装器无法覆盖旧服务，再使用同一目录下的卸载器后重新安装：

```powershell
$uninstaller = 'C:\Program Files\Clash Verge\resources\clash-verge-service-uninstall.exe'
$installer = 'C:\Program Files\Clash Verge\resources\clash-verge-service-install.exe'

Start-Process -FilePath $uninstaller -Verb RunAs -Wait
Start-Process -FilePath $installer -Verb RunAs -Wait
sc.exe query clash_verge_service
```

不要在第一步就使用 `sc.exe delete`，除非卸载器已经失败且确认 SCM 中仍有孤立的 `clash_verge_service` 注册项。

### 4.4 重启应用并验证 Service/TUN

服务注册完成后，重新启动 Clash Verge。日志中应出现：

```text
Starting core in service mode
服务成功启动核心
```

然后在应用中启用 TUN。验证结果应满足：

- 运行模式显示为 Service，而不是 Sidecar；
- TUN 可以开启；
- 日志不再出现 `owner credential path has an unexpected owner`；
- `clash_verge_service` 仍为 `RUNNING`。

启动切换期间偶尔出现一次 named pipe `os error 2` 属于服务接管过程中的短暂重试；如果随后出现 `服务成功启动核心`，不需要删除目录。

## 5. 旧锁的条件分支

旧锁不是本次属主错误的首要修复项。只有同时满足以下条件时才处理：

1. `sc.exe query clash_verge_service` 返回 1060；
2. 没有 `clash-verge-service.exe` 进程；
3. 服务目录中确实存在陈旧的 `.repair.lock` 或旧 runtime 状态文件；
4. 当前安装器反复执行仍不能注册服务。

管理员 PowerShell 中先备份服务目录：

```powershell
$serviceRoot = 'C:\ProgramData\clash-verge-service'
$backupRoot = "$serviceRoot.bak-$(Get-Date -Format 'yyyyMMdd-HHmmss')"
Copy-Item -LiteralPath $serviceRoot -Destination $backupRoot -Recurse -Force
```

确认服务和应用进程都已停止后，只删除明确的陈旧状态文件：

```powershell
Remove-Item -LiteralPath "$serviceRoot\bin\.repair.lock" -Force -ErrorAction SilentlyContinue
Remove-Item -LiteralPath "$serviceRoot\runtime\clash-verge-service.pid" -Force -ErrorAction SilentlyContinue
Remove-Item -LiteralPath "$serviceRoot\runtime\clash-verge-service.owner.lock" -Force -ErrorAction SilentlyContinue
```

随后用当前安装包重新运行 `clash-verge-service-install.exe`。不要在未确认前删除整个 `C:\ProgramData\clash-verge-service`。

## 6. 多台机器的排查记录

建议每台机器记录以下信息，便于区分问题类型：

```powershell
$appDataRoot = Join-Path $env:APPDATA 'io.github.clash-verge-rev.clash-verge-rev'
$service = Get-CimInstance Win32_Service -Filter "Name='clash_verge_service'" -ErrorAction SilentlyContinue

[ordered]@{
    User = [System.Security.Principal.WindowsIdentity]::GetCurrent().Name
    Sid = [System.Security.Principal.WindowsIdentity]::GetCurrent().User.Value
    AppDataOwner = (Get-Acl -LiteralPath $appDataRoot).Owner
    ServiceState = $service.State
    ServiceStartName = $service.StartName
    ServicePath = $service.PathName
} | Format-List
```

正常状态的关键条件是：

```text
AppDataOwner = 当前登录用户
ServiceState = Running
ServiceStartName = LocalSystem
```

## 7. 修复结论

本问题的最小修复顺序是：

1. 确认当前用户 SID 和应用数据目录属主；
2. 将应用数据根目录属主改回当前用户；
3. 确认 token 文件仍为当前用户拥有的 32 字节文件；
4. 使用当前版本安装器注册/重装服务；
5. 重启应用，确认 Service 模式和 TUN。

不要把回退版本当作权限修复，也不要把所有服务启动失败都归因于 `.repair.lock`。属主错误、协议版本不一致、服务未注册和陈旧锁是四种不同状态，应按日志分别处理。
